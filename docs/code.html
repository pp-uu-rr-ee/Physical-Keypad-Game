ส่วนที่ 5

อธิบายโค้ดอย่างละเอียด

ไฟล์ keypad_game.ino ยาว 436 บรรทัด แบ่งเป็นการตั้งค่า ตัวแปรสถานะ ฟังก์ชันย่อย 10 ฟังก์ชัน และ setup() / loop() ตัวเลขด้านซ้ายของโค้ดแต่ละส่วนคือเลขบรรทัดจริงในไฟล์

1. ภาพรวมการทำงาน

โปรแกรมทำงานเป็น State Machine ที่มี 3 สถานะ เก็บในตัวแปร state และในสถานะ "เล่น" ยังมีสถานะย่อย feedback สำหรับแสดงข้อความชั่วคราว 1 วินาที ทุกอย่างทำงานใน loop() โดยไม่ใช้ delay() เลย จึงอ่านปุ่มและนับเวลาได้พร้อมกัน

state = 0
รอเริ่ม
กด #
→
state = 1
กำลังเล่น
เวลา = 0
→
state = 2
หมดเวลา

จากสถานะ 2 กด # อีกครั้งจะกลับไปสถานะ 1 (เริ่มรอบใหม่)

ลำดับการเรียกฟังก์ชัน

  • loop() → readKey() → handleKey()
  • handleKey() → calculate() / show()
  • startRound() → newPuzzle() → resetAnswer()
  • show() → secondsLeft() / clearLine()

ค่า feedback

  • 0 ไม่มีข้อความ (รับปุ่มตามปกติ)
  • 1 ตอบถูก → ไปโจทย์ใหม่
  • 2 ใช้เลขไม่ครบ → ทำโจทย์เดิม
  • 3 ตอบผิด → ทำโจทย์เดิม

4. readKey() — สแกน Keypad

        

        

          
ฟังก์ชันนี้สแกน Keypad เองโดยไม่ใช้ไลบรารี Keypad.h ขณะพักขาทุกขาเป็น INPUT_PULLUP คืออ่านได้ HIGH

          
    
            
  1. บรรทัด 46–48 เลือกแถวที่ r โดยเปลี่ยนเป็น OUTPUT แล้วส่ง LOW รอ 5 µs ให้แรงดันในสายนิ่ง
    2. 
            
  2. บรรทัด 50–55 อ่านทั้ง 4 คอลัมน์ ถ้าคอลัมน์ c อ่านได้ LOW แปลว่าปุ่มที่ (r, c) ถูกกดเชื่อมแถวกับคอลัมน์ไว้ คืนแถวเป็น INPUT_PULLUP ก่อนแล้วจึง return keys[r][c]
    3. 
            
  3. บรรทัด 57 ถ้าไม่เจอ คืนแถวเป็น INPUT_PULLUP แล้วไปแถวถัดไป
    4. 
            
  4. บรรทัด 60 ไม่มีปุ่มใดถูกกด คืนค่า 0
    5. 
          

          

            ทำไมคืนเป็น INPUT_PULLUP แทนการส่ง HIGH? ถ้าส่ง HIGH แบบ OUTPUT แล้วผู้เล่นกดสองปุ่มในคอลัมน์เดียวกันพร้อมกัน
            จะเกิดการลัดวงจรระหว่างขาที่เป็น HIGH กับขาที่เป็น LOW การใช้ pull-up ภายใน (~20–50 kΩ) จำกัดกระแสไว้ จึงปลอดภัยต่อบอร์ด
          

        

      


      
      

        
5. calculate() — คำนวณ

        

        

          รับตัวตั้ง a ตัวกระทำ b และเครื่องหมาย op
          แล้วคืนผลลัพธ์เป็น float กรณีหารด้วยศูนย์จะคืน NAN (Not a Number)
          ซึ่งเมื่อนำไปคำนวณต่อก็ยังเป็น NAN และถูกตรวจจับด้วย isfinite() ทำให้ตอบผิดเสมอ
          ถ้า op ไม่ตรงกับเครื่องหมายใดจะคืน a กลับไปตามเดิม
          ฟังก์ชันนี้ใช้ทั้งตอนสุ่มโจทย์และตอนผู้เล่นตอบ จึงคำนวณด้วยกติกาเดียวกันแน่นอน
        

      


      
      

        
6. secondsLeft() — เวลาที่เหลือ

        

        
    
          
  • elapsed คือเวลาที่ผ่านไปตั้งแต่เริ่มรอบ การลบแบบ unsigned ทำให้ยังถูกต้องแม้ millis() วนกลับเป็น 0 (ทุก ~49.7 วัน)
    • 
          
  • เวลาทั้งหมด = 100,000 ms + โบนัส ทุกครั้งที่ตอบถูกเวลารวมจะยืดออก 10 วินาที
    • 
          
  • + 999UL คือการปัดเศษขึ้น (ceiling) เช่น เหลือ 99,001 ms จะแสดง 100 วินาที และจะแสดง 0 ก็ต่อเมื่อหมดเวลาจริงเท่านั้น
    • 
        

      


      
      

        
7. clearLine() และ show() — แสดงผล

        

        

          

            clearLine() พิมพ์ช่องว่าง 16 ตัวทับแถวเดิมแล้วย้ายเคอร์เซอร์กลับต้นแถว เร็วกว่าและกะพริบน้อยกว่า
            lcd.clear() ที่ล้างทั้งจอ
          

          
show() ทำงานเฉพาะเมื่อกำลังเล่น (state == 1) และบันทึก lastSeconds ไว้เพื่อให้ loop() รู้ว่าวาดจอไปแล้ว

          

            

              
แถวบน (บรรทัด 103–109)

              
T:24 87s S:3

              
T = เป้าหมาย, ตามด้วยวินาทีที่เหลือ, S = คะแนน

            

            

              
แถวล่าง (บรรทัด 112–145)

              
- 2 - 4 =3.0*

              
ถ้ามี feedback จะแสดงข้อความแล้ว return ทันที ไม่เช่นนั้นแสดงตัวเลข (ใช้แล้วเป็น -), = ผลลัพธ์ทศนิยม 1 ตำแหน่ง และเครื่องหมายที่รออยู่

            

          

        

      


      
      

        
8. resetAnswer() — ล้างคำตอบ

        

        

          คืนค่าทุกช่องของ used เป็น false และรีเซ็ตตัวนับ ผลลัพธ์ เครื่องหมาย
          โดย ไม่เปลี่ยน numbers และ goal
          ใช้ตอนกด *, หลังตอบผิด และเป็นขั้นตอนสุดท้ายของ newPuzzle()
        

      


      
      

        
9. newPuzzle() — สุ่มโจทย์ที่มีคำตอบแน่นอน

        

        

          
หัวใจของเกมคือการสร้างโจทย์ "ย้อนกลับ" — สุ่มคำตอบก่อน แล้วใช้ผลลัพธ์นั้นเป็นเป้าหมาย จึงรับประกันว่าทุกข้อมีทางแก้

          
    
            
  1. บรรทัด 166–168 สุ่มเลข 1–9 จำนวน 4 ตัว (random(1, 10) ไม่รวมค่าบน)
    2. 
            
  2. บรรทัด 170–178 นำตัวเลขมาคำนวณจากซ้ายไปขวาด้วยเครื่องหมายสุ่ม แบบเดียวกับที่ผู้เล่นกด
    3. 
            
  3. บรรทัด 180–181 ตัดทิ้งถ้าผลเป็น NAN/อนันต์ หรืออยู่นอกช่วงประมาณ 10–99
    4. 
            
  4. บรรทัด 183–190 ผลลัพธ์ต้องเป็นจำนวนเต็ม — ใช้ fabs(value - target) < 0.001 แทน == เพราะ float มีความคลาดเคลื่อน เช่น 7 ÷ 3 × 3 อาจได้ 6.9999998
    5. 
            
  5. บรรทัด 194–200 ถ้าสุ่มครบ 500 ครั้งยังไม่ได้ (โอกาสน้อยมาก) ใช้โจทย์สำรอง 1 2 3 4 → 24 ซึ่ง (1+2+3)×4 = 24
    6. 
            
  6. บรรทัด 203–209 สลับตำแหน่งด้วยอัลกอริทึม Fisher–Yates เพื่อไม่ให้ลำดับตัวเลขบนจอบอกลำดับของคำตอบ
    7. 
            
  7. บรรทัด 211 เรียก resetAnswer() เตรียมรับคำตอบใหม่
    8. 
          

        

      


      
      

        
10. startRound() และ endRound()

        

        
    
          
  • randomSeed(micros() ^ analogRead(A3)) กำหนดเมล็ดสุ่มจากเวลาระดับไมโครวินาทีที่ผู้เล่นกด # (คาดเดาไม่ได้) XOR กับสัญญาณรบกวนจากขา A3 ที่ปล่อยลอย ทำให้โจทย์แต่ละรอบไม่ซ้ำกัน
    • 
          
  • รีเซ็ตคะแนน โบนัส และ feedback สร้างโจทย์แรก บันทึกเวลาเริ่ม แล้วเปลี่ยนเป็นสถานะเล่น
    • 
          
  • lastSeconds = -1 บังคับให้จอวาดใหม่แน่นอนในรอบแรก
    • 
          
  • endRound() เปลี่ยนเป็นสถานะ 2 และแสดงคะแนนพร้อมคำแนะนำให้กด # เล่นใหม่
    • 
        

      


      
      

        
11. handleKey() — ตรรกะการกดปุ่ม

        
ฟังก์ชันที่ยาวที่สุด รับปุ่มที่ผ่านการ debounce แล้วตัดสินว่าจะทำอะไร โดยตรวจเงื่อนไขทีละชั้นและ return ทันทีเมื่อทำงานเสร็จ


        
11.1 ด่านตรวจก่อนรับปุ่ม

        

        
    
          
  • ถ้าไม่ได้อยู่ในสถานะเล่น รับเฉพาะ # เพื่อเริ่มรอบ ปุ่มอื่นถูกเพิกเฉย
    • 
          
  • ตรวจเวลาอีกชั้นหนึ่ง ป้องกันการตอบหลังเวลาหมดในจังหวะเดียวกัน
    • 
          
  • ระหว่างแสดงข้อความ 1 วินาที ล็อกปุ่มทั้งหมด ไม่ให้กดซ้อน
    • 
          
  • * เรียก resetAnswer() ล้างคำตอบ
    • 
        


        
11.2 กดตัวเลข

        

        
    
          
  • รับตัวเลขเฉพาะเมื่อ needNumber เป็น true และยังใช้ไม่ครบ 4 ตัว ทำให้ต้องกดสลับ เลข-เครื่องหมาย-เลข
    • 
          
  • key - '0' แปลงตัวอักษร ASCII เป็นตัวเลข เช่น '7' (55) − '0' (48) = 7
    • 
          
  • ลูปค้นหา ช่องแรกที่ยังไม่ถูกใช้ และมีค่าตรงกัน วิธีนี้รองรับโจทย์ที่มีเลขซ้ำ เช่น 3 3 8 8 ได้ถูกต้อง ถ้าไม่พบ (กดเลขที่ไม่มีหรือใช้หมดแล้ว) ปุ่มจะถูกเพิกเฉย
    • 
          
  • ตัวเลขแรกกลายเป็นผลลัพธ์ตั้งต้น ตัวถัดไปนำไปคำนวณกับผลสะสมด้วยเครื่องหมายที่เลือกไว้
    • 
          
  • ทำเครื่องหมาย used, นับเพิ่ม, ล้างเครื่องหมาย และเปลี่ยนเป็นรอเครื่องหมาย
    • 
        


        
11.3 กดเครื่องหมาย

        

        

          รับเครื่องหมายได้เมื่อมีตัวเลขแล้วอย่างน้อย 1 ตัว ยังไม่ครบ 4 ตัว และกำลังรอเครื่องหมายอยู่
          ใช้ ternary operator ซ้อนกันแปลง A/B/C/D เป็น + − * / แล้วกลับไปรอตัวเลข
          (ถ้าผู้เล่นอยากเปลี่ยนเครื่องหมายต้องกด * ล้างแล้วเริ่มใหม่)
        


        
11.4 กด # ส่งคำตอบ

        

        

          

            
เงื่อนไขผล

            
              
count == 0ข้ามข้อ — สุ่มโจทย์ใหม่ทันที ไม่เสียคะแนน (แต่เสียเวลา)

              
count < 4feedback = 2 → Use all 4 nums!

              
needNumber || operationfeedback = 3 — เงื่อนไขป้องกันไว้ก่อน (ในทางปฏิบัติไม่เกิด เพราะกดเครื่องหมายหลังเลขตัวที่ 4 ไม่ได้)

              
|result − goal| < 0.001ถูก — score++, timeBonus += 10000, feedback = 1

              
อื่น ๆผิด — feedback = 3 → Incorrect!

            
          

        

        
ทุกกรณีที่ตั้ง feedback จะบันทึก feedbackStart = millis() เพื่อให้ loop() นับ 1 วินาทีแล้วล้างข้อความเอง

      


      
      

        
12. setup() — เตรียมระบบ

        

        

          ทำงานครั้งเดียวเมื่อเปิดเครื่องหรือกดรีเซ็ต ตั้งขา Keypad ทั้ง 8 ขาเป็น INPUT_PULLUP
          เริ่มต้นจอ LCD เปิดไฟพื้นหลัง และแสดงหน้าจอต้อนรับ Math Game 100s / # Start round
          ขณะนี้ state ยังเป็น 0 (รอเริ่ม)
        

      


      
      

        
13. loop() — วงรอบหลักและการกรองปุ่มเด้ง


        
13.1 จัดการเวลาและข้อความ

        

        
    
          
  • ถ้าเวลาหมดระหว่างเล่น เรียก endRound() ทันที แม้ผู้เล่นไม่ได้กดปุ่ม
    • 
          
  • ถ้าข้อความแสดงครบ FEEDBACK_MS (1 วินาที) แล้ว ล้าง feedback — ตอบถูกไปโจทย์ใหม่ นอกนั้นทำโจทย์เดิม
    • 
          
  • วาดจอใหม่ เฉพาะเมื่อวินาทีเปลี่ยน แทนที่จะวาดทุกรอบ ลดการส่งข้อมูล I2C และทำให้จอไม่กะพริบ
    • 
        


        
13.2 Debounce — กรองการเด้งของปุ่ม

        

        

          

            หน้าสัมผัสของปุ่มกลไกจะ "เด้ง" ติด-ดับหลายครั้งในช่วงไม่กี่มิลลิวินาทีแรก ถ้าไม่กรอง การกดครั้งเดียวอาจถูกนับหลายครั้ง
            โค้ดนี้ใช้ตัวแปร static 3 ตัวซึ่งเก็บค่าไว้ข้ามรอบของ loop()
          

          
    
            
  • previous ค่าที่อ่านได้ล่าสุด — ทุกครั้งที่ค่าเปลี่ยน จะจดเวลาไว้ใน changed
    • 
            
  • ค่าต้อง คงที่ติดต่อกันอย่างน้อย 25 ms จึงถือว่าเชื่อถือได้
    • 
            
  • accepted ค่าที่ยอมรับแล้ว — เรียก handleKey() เฉพาะเมื่อค่าที่นิ่งแล้วต่างจากเดิม และไม่ใช่ 0
    •
